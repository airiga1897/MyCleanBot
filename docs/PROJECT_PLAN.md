# План MyCleanBot

## Назначение

MyCleanBot обслуживает до десяти приглашённых пользователей. Каждый подключает
собственный Telegram-аккаунт и добавляет личные запрещённые фразы. Новые исходящие
сообщения, edits и captions проверяются сразу после получения Telegram update.

Пользователь не может приостановить фильтр или удалить правило напрямую. Он создаёт
запрос, который рассматривает оператор. Владелец Telegram-аккаунта всегда сохраняет
техническую возможность отозвать сессию в разделе «Устройства».

## Управление

- VPN-only пользовательский кабинет и Django Admin для оператора.
- Регистрация по одноразовой ссылке со сроком действия 24 часа.
- QR authorization; phone/OTP/2FA — резервный сценарий.
- Веб-статус и `/mc_status` в «Избранном».
- `/mc_status` редактируется в краткий ответ и удаляется через 15 секунд.
- Telegram-команд для паузы, правил или отключения нет.

## Фильтрация

- Unicode casefold и сворачивание пробельных символов.
- Подстрочное совпадение с личными правилами пользователя.
- Проверка body, caption, visible URL и скрытого `MessageEntityTextUrl`.
- Для URL проверяются raw, однократно percent-decoded и IDN Unicode варианты.
- Страницы и redirects не загружаются.
- Audit не содержит текстов, URL, peer ID или названий чатов.

## Архитектура

- Один immutable image, два процесса: Django web и Telethon supervisor.
- До десяти AccountRunner внутри supervisor.
- PostgreSQL, secrets, backups, monitoring и deployment принадлежат
  `AI_Service_Platform`.
- Собственного production PostgreSQL контейнера у приложения нет.
- Один AccountRunner на аккаунт обеспечивается PostgreSQL advisory lock.
- Правила и StringSession зашифрованы отдельным пользовательским DEK; DEK обёрнут
  platform master key.

## Ограничения

- Удаление происходит после отправки и не гарантирует блокировку уведомления.
- Сообщения от имени канала или anonymous admin не входят в v1.
- Preprod Telegram-сессии нет; интеграция проверяется mocks в CI.
