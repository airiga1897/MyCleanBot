# План MyCleanBot

## Назначение

MyCleanBot обслуживает до десяти приглашённых пользователей. Каждый подключает
собственный Telegram-аккаунт и добавляет личные запрещённые фразы. Новые входящие
и исходящие сообщения, edits и captions проверяются после получения Telegram update.

Пользователь выбирает направление и режим каждого правила. Незащищённое правило
удаляется сразу; удаление защищённого правила рассматривает оператор. Владелец
Telegram-аккаунта всегда сохраняет техническую возможность отозвать сессию в
разделе «Устройства».

## Управление

- VPN-only пользовательский кабинет и отдельный русскоязычный `/operator/`.
- Django Admin используется только как резервный технический интерфейс.
- Регистрация по одноразовой отзываемой ссылке со сроком действия 24 часа.
- Активные приглашения резервируют места в общем лимите десяти аккаунтов.
- QR authorization; phone/OTP/2FA — резервный сценарий с автоматическим ожиданием
  результата worker и возможностью отмены или смены способа.
- Веб-статус и `/mc_status` в «Избранном».
- `/mc_status` редактируется в краткий ответ и удаляется через 15 секунд.
- Telegram-команд для паузы, правил или отключения нет.

## Фильтрация

- Unicode casefold и сворачивание пробельных символов.
- Подстрочное совпадение с личными правилами пользователя.
- Проверка body, caption, visible URL и скрытого `MessageEntityTextUrl`.
- Для URL проверяются raw, однократно percent-decoded и IDN Unicode варианты.
- Страницы и redirects не загружаются.
- Направления правила: `incoming`, `outgoing`, `both`.
- `observe` только фиксирует совпадение, `warn` также предупреждает владельца,
  `enforce` пытается удалить сообщение.
- Исходящее сообщение удаляется с отзывом. Входящее в личном чате или обычной
  группе удаляется из истории подключённого аккаунта.
- В супергруппе или канале входящее удаляется для всех только при наличии права
  удаления; иначе фиксируется безопасный результат отказа.
- Audit не содержит текстов, URL, peer ID или названий чатов.
- Диагностика аккаунта содержит только время, направление и результат последнего
  обработанного update.

## Полная история

- Realtime `NewMessage` и `MessageEdited` всегда имеют приоритет.
- Вся доступная облачная история всех диалогов проверяется отдельной фоновой
  задачей небольшими пакетами.
- Progress сохраняется после пакета; после рестарта worker продолжает с
  обезличенного cursor без текста, peer ID и названия чата.
- Новое или изменённое правило `enforce` автоматически создаёт фоновое задание
  для своей текущей ревизии и выбранной области чатов. Задания выполняются
  последовательно для одного Telegram-аккаунта, сохраняют обезличенный cursor и
  отменяются при появлении более новой ревизии правила.
- Rollout не запускает очистку для неизменённых существующих правил. Повторную
  проверку конкретного правила пользователь может запустить из кабинета.
- Исторические совпадения в private chat, Saved Messages и basic group удаляются
  только из истории подключённого аккаунта (`revoke=false`).
- В channel и supergroup совпадения учитываются, но массовое глобальное удаление
  history scan не выполняет.
- Secret chats не входят в облачную историю MTProto и не сканируются.
- Уже удалённые сообщения восстановить средствами MyCleanBot нельзя.

## Telegram Mini Apps

- Правила allow/deny изолированы по `TelegramAccount`.
- Основной идентификатор — `bot_id`; также поддерживаются username, название,
  keyword и безопасное regex-подмножество.
- Установленные attachment/side-menu приложения сверяются по MTProto сразу после
  `UpdateAttachMenuBots` и периодически.
- Режим по умолчанию — `observe`; `warn` добавляет предупреждение, `enforce`
  отключает menu entry, опционально блокирует бота и реактивно удаляет сообщения.
- Переход существующего пользователя в `enforce` никогда не выполняется миграцией
  или deployment автоматически.
- Опция «Уведомлять оператора в кабинете» создаёт минимальное оповещение без
  email и SMTP. Одинаковые непрочитанные события объединяются: сохраняются
  первое и последнее время и число повторов. Технический Mini Apps audit
  остаётся отдельным.

## Составные правила и область чатов

- Одно правило содержит необязательное зашифрованное название и до 50 фраз,
  объединённых логическим OR.
- Правило действует во всех чатах либо в нескольких выбранных пользователем
  диалогах. Worker обновляет каталог диалогов раз в
  `TELEGRAM_DIALOG_SYNC_SECONDS`; peer ID хранится только как необратимый
  fingerprint, название — зашифрованно.
- Усиление защищённого правила применяется сразу. Удаление или замена фразы,
  сужение направления/области, снижение режима и снятие защиты оформляются
  одним атомарным запросом оператору; до решения действует прежняя ревизия.
- Пользователь видит только собственные диалоги, правила, задания и события.

## Пользователи и VPN

- Блокировка пользователя в `/operator/` прекращает запуск его worker,
  отменяет активную авторизацию и фоновые задания.
- MyCleanBot не имеет административного доступа к SoftEther. Отзыв VPN-доступа
  выполняется отдельной платформенной командой по ID приглашения.
- Для каждого приглашения используется персональная VPN-учётка; `operator_arm`
  не передаётся пользователям.

## Архитектура

- Один immutable image, два процесса: Django web и Telethon supervisor.
- До десяти AccountRunner внутри supervisor.
- PostgreSQL, secrets, backups, monitoring и deployment принадлежат
  `AI_Service_Platform`.
- Собственного production PostgreSQL контейнера у приложения нет.
- Один AccountRunner на аккаунт обеспечивается PostgreSQL advisory lock.
- Правила и StringSession зашифрованы отдельным пользовательским DEK; DEK обёрнут
  platform master key.

## Ограничения

- Обработка происходит после Telegram update и не гарантирует блокировку
  уведомления или кратковременного показа сообщения.
- Локальное удаление входящего сообщения не удаляет его у других участников.
- Глобальное удаление в супергруппе или канале зависит от прав аккаунта и правил
  Telegram.
- Сообщения от имени канала или anonymous admin могут иметь ограничения,
  определяемые доступными MTProto update и правами.
- Preprod Telegram-сессии нет; интеграция проверяется mocks в CI.

## Будущее: AI-помощник

AI-классификация не входит в первый production runtime. Возможная следующая фаза —
только opt-in помощник в `observe`, который по минимальным метаданным предлагает
правило человеку. AI не получает Telegram session или полный текст, не включает
`enforce` и не выполняет блокировку без явного подтверждения.
